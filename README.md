# 本地知识库助手 · 学习版

这是一个逐步学习 RAG（检索增强生成）的 Python 项目：使用 Streamlit 构建网页，在本机读取资料、生成文本向量并通过 Chroma 检索，再把参考片段交给 DeepSeek 生成回答。

**入口是 `app.py`。** 项目使用本地嵌入模型，但 DeepSeek 回答通过远程 API 生成；知识库问答会将检索到的片段、来源、本次问题和此前对话发送给 DeepSeek。

## 已实现的功能

- **普通对话**：使用 DeepSeek API，在网页中提问并显示回答、返回模型和 Token 用量。
- **知识库问答**：自动使用最新本地 Chroma 知识库，用当前问题检索相关片段，将片段作为参考资料提供给 DeepSeek；回答下可查看片段来源和相似度。
- **本地+互联网联合检索**：先检索选定的本地知识库，再调用 DeepSeek Search API 搜索当前问题，将本地片段及最多3条网页摘要一起交给 DeepSeek 回答。结果统一编号，网页标题、链接、摘要和时间随对话保存，可以重新查看。
- **资料增量更新**：将 TXT、Markdown（`.md`、`.markdown`）、PDF 或 DOCX 放入 `资料/`；启动更新时只解析和向量化新增或修改的资料，复用未变化文件的向量。
- **启动自动更新**：每次重启服务后首次打开网页，自动增量同步 `资料/`，并在 `更新历史/` 写入一份 Word 记录。
- **本地对话历史**：每个新对话在首次提问时创建 JSON 文件；下拉框可选择并继续已有对话，回答、模型名称、用量和参考片段会随历史保存。
- **旧索引迁移**：无可用 Chroma 集合时，可以将最新一份兼容的旧 JSON 索引导入 Chroma；源文件保留。

## 项目架构

```text
浏览器
  │ 访问本地 Streamlit 网页
  ▼
app.py：页面入口、会话选择、模式选择和 DeepSeek 请求
  ├─ chat_ui.py：显示聊天消息、Token 用量及参考片段
  ├─ upload_ui.py：启动更新及状态显示（保留原模块名）
  │    └─ auto_update.py：执行更新并保存 Word 记录
  │         └─ knowledge_upload.py：组织知识库更新
  │              ├─ document_monitor.py：扫描资料文件信息
  │              ├─ document_reader.py：读取资料并切分文本
  │              └─ incremental_index.py：复用向量并保存新快照
  ├─ rag_demo.py：检索参考资料，组装问题、历史和参考片段
  │    └─ chroma_index.py：查询本地 Chroma
  │         └─ embedding_demo.py：本地加载模型并生成向量
  └─ history.py：创建、读取和保存 Histor 中的对话
```

`app.py` 是 Streamlit 脚本。用户交互会触发脚本重新执行；`st.session_state` 用于保留当前网页会话的对话和选择，长期保存则由本地文件负责。

### 联合检索说明

页面的“对话模式”可选择普通对话、仅本地知识库问答或“本地+互联网联合检索”。联合模式复用 `.env.local` 中的 `DEEPSEEK_API_KEY`，不需要额外安装搜索包或填写其他 Key。

搜索服务只收到本轮问题，问题最多128个字符；本地片段、搜索摘要和此前对话用于后续DeepSeek回答。网页显示可点击的搜索来源，搜索时间与网页发布时间分别记录。搜索结果是接口提供的摘要，不表示已经读取网页全文；网页内容可能过时、不完整或包含错误，应查看原始来源。

DeepSeek Search 与生成回答是两个独立的接口：搜索成功且有结果时按次收费，生成回答按Token计费；实际费率以 [DeepSeek官方说明](https://api-docs.deepseek.com/guides/search/) 为准。本地检索失败时不会发送搜索请求。搜索失败或结果为空时会明确报错，不会悄悄当作联合检索成功；可重试或切换到“知识库问答”。

### 更新知识库的数据流

```text
服务启动后首次打开网页
    ↓
扫描资料/ 下文件的大小和修改时间，比较索引记录的文件清单
    ↓
解析并切分新增、修改的文件，仅为这些片段生成向量
    ↓
从旧集合复制未修改文件的片段和向量，与新向量一起写入新的 Chroma 集合
    ↓
写入完成且数量核对通过后，网页自动选中新集合
```

启动自动更新以最新可用知识库为基线，并按照当前资料目录同步删除。未变化的文件不再打开解析或重新生成向量，修改的文件重新处理。没有有效变化时直接使用原集合。

为了在更新失败时保留可用知识库，系统先创建新集合，分批复制未变化的旧向量，并对新集合进行校验。**只有新集合成功完成并确认可用之后，才删除其他已完成的旧知识库集合**；没有文件变化时，也会保留当前最新集合并清理其他旧集合。复制旧向量仍会消耗时间和磁盘空间。首次处理**旧版集合**时，因为它没有保存文件变化信息，需要读取当前资料并与旧片段逐一核对：相同的文件复用向量，不同或新增的文件生成新向量；之后的更新才可以跳过未变化文件的解析。

清理只针对本项目 `kb-` 命名的已完成 Chroma 集合，不删除资料原文件、对话历史、更新记录或旧 JSON 文件。未完成的集合可能正在构建，因此不会自动删除；清理失败时网页和 Word 记录会显示未成功清理的集合，并在后续更新时重试。删除旧集合后历史聊天中的参考片段仍可显示，但依赖旧集合的历史检索评估无法直接重跑。Chroma 删除集合不保证数据库文件立即变小，也可能留下未再被当前数据库引用的向量索引目录；本程序不手动删除 Chroma 内部目录。

增量判断使用文件大小与纳秒修改时间，不读取旧文件全部内容，因此人为保持大小和修改时间不变的替换可能无法被识别。切分规则变化时会重新核对片段；资料在更新中变化、待处理文件读取失败或写入失败时不会发布不完整的新集合。发生错误时可处理问题后重启服务进行自动更新。

### 启动自动更新与 Word 记录

Streamlit 在浏览器连接后才执行页面脚本，因此自动更新发生在**每次启动服务后首次打开网页时**。同一服务进程通过 `st.cache_resource` 共用一次启动结果；聊天、刷新和新开会话不会重复建库。多进程各自执行一次。服务运行期间手动放入的文件会在下次重启并打开网页时更新。

每次启动更新（包括失败和无变化）会尝试在项目根目录 `更新历史/` 保存独立的 `.docx`，记录时间、结果、文件变化、向量复用数量和提示，不复制原文或 API Key。记录保存失败时网页会单独提示，不会把已经成功的建库误报为失败。更新不会调用 DeepSeek。

### 知识库问答的数据流

```text
用户问题 → 保存用户消息到 Histor
    ↓
问题加检索提示 → 本地模型生成问题向量
    ↓
Chroma 使用余弦距离检索所选集合（默认返回前 3 个片段）
    ↓
组织参考片段、来源、本次问题及此前对话
    ↓
DeepSeek 远程 API 生成回答
    ↓
网页显示回答和参考片段 → 保存回答、模型名称、Token 用量及来源
```

Chroma 当前使用 HNSW 近似检索；检索结果可能与逐个精确比较略有不同。显示的相似度由 `1 - 余弦距离` 得到，不代表答案正确的概率。普通对话则直接发送对话消息，不检索知识库。

## 安装和启动

以下命令在项目根目录执行。当前项目已在 macOS、Python 3.13 的 `application-llm-universe` Conda 环境中验证；其他系统或 Python 版本需要自行确认依赖兼容性。

### 1. 创建环境并安装依赖

如果已有项目环境，可先激活它；也可以创建一个新的 Python 3.13 环境：

```bash
conda create -n application-llm-universe python=3.13
conda activate application-llm-universe
```

如果同名环境已经存在，直接使用 `conda activate`，不需要重复创建。

```bash
python -m pip install -r requirements.txt
```

`requirements.txt` 包含网页和 API 的主依赖，并引用文档读取、向量模型、Chroma 的三个分项依赖文件。依赖安装需要网络；本地推理时模型不会自动下载。

### 2. 配置 DeepSeek API Key

在项目根目录创建 `.env.local`：

```dotenv
DEEPSEEK_API_KEY=在这里填写自己的Key
```

程序从这个文件读取 Key。`.env.local` 已由 `.gitignore` 排除；请不要把实际 Key 写进代码或提交到 Git。

### 3. 准备本地嵌入模型

在 `models/bge-small-zh-v1.5/` 中准备以下五个文件：

```text
model_optimized.onnx
config.json
tokenizer.json
tokenizer_config.json
special_tokens_map.json
```

项目使用 FastEmbed 的 `BAAI/bge-small-zh-v1.5` 配置，运行时只读取该目录，不会自动下载。可以从原项目已准备好的同款模型目录复制这些文件，或自行从 [Qdrant 的模型文件页面](https://huggingface.co/Qdrant/bge-small-zh-v1.5/tree/main)准备对应文件。模型目录约 91 MiB，当前 `.gitignore` 不排除该目录，提交前请检查仓库状态。

### 4. 启动网页

```bash
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

浏览器打开 `http://127.0.0.1:8503`。停止服务时，在运行命令的终端按 `Ctrl+C`。

在 PyCharm 中可以新建 Python 运行配置：选择项目环境作为解释器，**Module name** 填写 `streamlit`，参数填写 `run app.py --server.address 127.0.0.1 --server.port 8503`，工作目录设置为本项目根目录。随后可以用运行按钮启动。

## 使用方式

1. 将资料放入 `资料/` 文件夹，启动并首次打开网页后，等待自动增量更新完成。服务运行期间放入的文件会在下次重启并打开网页时更新。
2. 建库完成后，选择“本地+互联网联合检索”；也可以选择“知识库问答”或“普通对话”。系统自动使用最新的知识库。
3. 输入问题并查看回答。联合检索的问题最多128字，仅本地知识库问答最多200字；回答下可展开查看本地片段与网页摘要。
4. 使用“选择对话历史”继续已有对话，或选择“新对话”。新会话在首次提问后创建历史文件，文件名包含日期和首个问题。

TXT 和 Markdown 应为 UTF-8；PDF 按页读取、切分时不跨页。扫描版 PDF 需要先进行 OCR；旧版 `.doc` 需要先转换为 `.docx`。Word 图片、页眉页脚及复杂版式不保证完整提取；文件读取失败或部分页面没有文字时，网页会显示提示。

当前检索只使用本次输入的问题，不自动将前文代词改写为完整问题。检索片段和模型回答可能不准确，使用时应结合原文核对。

DeepSeek 当前启用思考模式，思考内容与最终回答共用输出 Token 额度。普通对话上限为 512，知识库问答上限为 8192，可在 `app.py` 中的 `CHAT_MAX_TOKENS` 和 `RAG_MAX_TOKENS` 调整。上限提高可能增加用量；如果达到输出或上下文限制，网页会提示缩短问题或历史。部分回答被截断时会保留并显示提醒。

## 本地数据与 Git

| 目录或文件 | 内容 | 当前忽略情况 |
| --- | --- | --- |
| `.env.local` | DeepSeek API Key | 已忽略 |
| `Histor/` | 明文聊天历史，可能包括参考片段 | 当前未忽略 |
| `models/` | 本地嵌入模型文件 | 当前未忽略 |
| `.local/chroma/` | Chroma 集合、向量、原文和来源 | 当前未忽略 |
| `.local/document_inventory.json` | 旧版资料检查记录 | 当前未忽略 |
| `vector_index/` | 旧 JSON 索引快照 | 当前未忽略 |
| `资料/上传/` | 以前上传的资料，仍参与自动更新 | 当前未忽略 |
| `更新历史/` | 更新结果、文件名和索引名称的 Word 记录 | 当前未忽略 |
| `资料/` 的其他内容 | 手动放入或复制的本地资料 | **默认未全部忽略**，上传 GitHub 前请检查 |

`.gitignore` 不会自动移除 Git 已经跟踪的文件或已有提交中的内容。历史记录、资料和索引均可能包含私人信息；选择知识库问答时，相关片段和对话会发送到 DeepSeek。请根据实际用途备份资料与历史；当前历史文件适合单会话使用，多个网页会话同时修改同一对话可能互相覆盖。

## 迁移旧 JSON 索引

如果项目已有 `vector_index/` 下的旧 JSON 快照，可运行：

```bash
python migrate_json_indexes.py
```

迁移脚本只在没有可用 Chroma 知识库时，校验并导入最新的一份旧 JSON 索引；已有知识库时会拒绝迁移，避免替换正在使用的最新知识库。原 JSON 文件不会被删除。资料变化后仍需要更新知识库。迁移脚本不读取 DeepSeek API Key，也不调用 DeepSeek。
