# 从头学习构建知识库助手

这个文件夹是独立的学习项目。我们会逐步添加功能，每一步都先理解并确认，再进行下一步。

当前网页已精简为上传与更新知识库、对话历史、对话模式、知识库选择及聊天，现已改用本地 Chroma。下文第一至第五步和“观察一次知识库问答过程”记录此前的学习过程，其中提到的 JSON 索引和学习演示目前不用于网页问答；相关 Python 文件仍保留供阅读。当前使用方式见第六、七步和“本地 Chroma”。

## 学习路线

1. 创建一个能显示标题的网页（已完成）。
2. 让用户输入问题，并理解页面交互和会话状态（已完成）。
3. 接入 DeepSeek，完成普通对话（已完成）。
4. 读取资料文件，理解文本切分（已完成）。
5. 将文字转换为向量，比较相似度，再建立索引并检索（已完成）。
6. 将检索结果交给 DeepSeek，完成知识库问答（已完成）。
7. 添加文件上传和知识库更新（已完成）。
8. 精简网页，并切换到本地 Chroma；后续逐步学习 RAG 评估和 LangChain。

后续步骤可能根据理解情况拆得更细；目前实现了网页、DeepSeek 普通对话、本地资料切分、向量索引、基于索引的问答以及上传资料更新索引。

## 第一步：创建网页

打开 `app.py`。它先导入 Streamlit，再设置浏览器标签页，最后显示网页正文标题和说明。Streamlit 是一个 Python 库，负责把这些代码展示成网页。

- `page_title` 设置浏览器**标签页**的标题。
- `st.title()` 设置网页**正文**的大标题。
- `st.caption()` 在标题下面显示较小的说明文字。

### 启动

打开终端，运行：

```bash
cd /Users/yadingyi/Desktop/AI-algorithm/application-llm-universe
/Users/yadingyi/miniconda3/envs/application-llm-universe/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

在浏览器打开 <http://127.0.0.1:8503>。终端保持运行，停止时在终端按 `Ctrl+C`。如果端口已被占用，可以换一个端口，并打开对应地址。

PyCharm 项目使用 `application-llm-universe` Conda 环境；本地 Chroma 固定依赖在 `requirements-chroma.txt` 中。相邻 `llm-universe/.venv` 的旧版 Chroma 不适用于当前代码，不要将两个项目的数据库目录混用。

## 第二步：输入问题

网页底部的输入框由 `st.chat_input()` 创建。输入文字并按回车或点击发送，输入内容会赋给变量 `question`。`if question:` 判断是否提交了内容；有内容时，`append()` 将它添加到消息列表。

每次交互时 Streamlit 会重新执行脚本。`st.session_state` 可以在同一个会话的重新执行之间保留数据。第二步中，我们用列表保存用户的问题，再用 `for` 循环和 `st.chat_message()` 按顺序显示。

## 第三步：DeepSeek 对话

学习版读取当前项目目录的 `.env.local` 中的 `DEEPSEEK_API_KEY`，不会在页面上显示 Key。它使用 `deepseek-flash` 进行普通对话；每次请求会把当前会话的消息列表发送给 DeepSeek，产生的费用由你的 DeepSeek 账户承担。这一步尚未使用知识库。

页面会显示自动重试上限。对于客户端判断为可重试的错误，首次请求失败后最多再尝试 5 次；并非所有错误都会触发重试。重试由客户端在后台进行，页面目前显示的是上限，不逐次显示重试进度。

模型请求中设置了 `temperature=0.1` 和 `reasoning_effort="max"`，并保持思考模式开启。DeepSeek 在思考模式下会忽略 `temperature`；关闭思考模式后该参数才生效。当前环境的 OpenAI SDK 较旧，因此通过 `extra_body` 传递 `reasoning_effort`。思考内容也会占用 `max_tokens` 的额度，当前 512 较小，复杂问题可能无法生成完整回答。

每次收到有效回答后，页面会显示接口返回的模型名称，以及本次请求的输入、输出和总 token 数，并与回答一起保存到历史文件。重新打开网页后，这些信息会随对应回答显示；之前没有保存这些信息的历史消息无法补回，如果接口没有返回也会显示提示。

## 本地保存聊天记录

网页的“选择对话历史”下拉框列出 `Histor/` 中的 JSON 文件，并提供“新对话”选项。新网页会话默认从新对话开始：提交第一个问题时，程序按北京时间日期和首个问题创建文件，例如 `2026-10-31_你好.json`；如果同名则加编号，长问题会截短，特殊字符会替换，原问题内容仍完整保存在文件里。尚未提问时不会创建空文件。

选择已有文件后会加载并继续该对话；原有的 `conversation.json` 也保留在下拉框中。问题提交时和回答生成后，程序分别保存消息；助手消息还包含模型名称和 Token 用量。如果模型调用失败，已保存的问题仍会保留。读取历史失败时程序会停止，以免覆盖原文件；写入失败时网页会提示。发送模型请求时只取每条消息的角色和内容，不把本地用量字段作为消息发送给 API。

历史文件是本机明文，文件名也包含首个问题，可能包含私人信息；`Histor/` 已加入 `.gitignore`。每次提问会把当前加载的完整对话发送给 DeepSeek，记录越长，请求的长度和费用可能越大。当前实现面向单个浏览器会话：请不要同时在多个标签页或服务实例中继续同一条历史，否则各会话可能用旧记录覆盖彼此的更新。第三步之前只存在于内存中的旧会话无法从磁盘恢复。

## 第四步：读取并切分本地资料

把 UTF-8 编码的 `.txt`、`.md`、`.markdown` 文件，或 `.pdf`、`.docx` 文件放在项目的 `资料/` 中，也可放入子文件夹。网页展开“学习：读取并切分本地资料”，点击按钮后，可选择资料并分页查看切分结果。默认每段最多 300 个字符，相邻两段重叠 50 个字符；字符位置从 0 开始，结束位置不包含在片段中。

原项目 `llm-universe/docs/` 已复制到 `资料/docs/`，保留教程和图片等资源的目录结构。当前读取程序会递归处理其中的 Markdown；图片、HTML 等文件保留在目录中，但不会被读取或切分。复制后的文件是独立副本，不会自动与原项目同步。

PDF 按页读取，片段保留 PDF 页码，不会跨页；扫描图片需要先 OCR，才可以读取文字。Word 读取 `.docx` 的正文段落和表格文字；旧版 `.doc` 需要先另存为 `.docx`。图片、页眉页脚等内容不会在本步骤提取，复杂版式和公式的提取效果需要人工核对。部分文件读取失败时会显示文件名和原因，其余文件仍继续处理。

PDF 和 Word 依赖 `requirements-documents.txt`，在使用的 Python 环境中可通过 `python -m pip install -r requirements-documents.txt` 安装。预览只在当前浏览器会话中保存，重新打开网页后可再次点击读取。

资料切分预览不会进行向量化、资料检索或基于资料回答。点击预览只在本机处理文件，不调用 DeepSeek。要在聊天中使用资料，还需要构建索引并选择知识库问答模式。

## 第五步：把一段文字转换为向量

展开“学习：把一段文字转换为向量”，输入不超过 200 个字符的文字，点击“生成向量”。程序使用项目内 `models/bge-small-zh-v1.5/` 的本地中文模型，在 CPU 上计算并显示全部 512 个数字。模型文件从原项目的本地缓存复制而来，生成向量时不需要 DeepSeek Key，也不会把输入发送到 DeepSeek。

首次点击会加载模型，可能稍慢；同一进程后续调用会复用模型。英文 ASCII 大写字母在向量化前转换为小写，显示的原文不变。模型依赖列在 `requirements-embedding.txt`，如需在新的 Python 环境运行，可通过 `python -m pip install -r requirements-embedding.txt` 安装。模型文件约 91 MB，已由 `.gitignore` 排除；如果缺少模型文件，需要从原项目模型缓存重新复制或自行准备。

## 第五步：比较两段文字的向量

展开“学习：比较两段文字的相似度”，输入两段文字，点击“计算相似度”。程序分别使用同一个本地模型生成向量，再计算余弦相似度。结果的理论范围是 -1 到 1，数值越高表示向量方向越接近，但它不是概率，也不能保证事实正确。页面还显示向量的前 8 个数字，可勾选查看完整向量。

## 第五步：与多个资料片段比较

先点击“读取并切分资料”，再展开“学习：从多段资料中找到相关片段”，输入问题并选择一个文件或全部资料。程序把问题和所选片段转换为向量，计算余弦相似度并显示排名靠前的片段及来源。问题使用 BGE 模型的检索提示前缀，文档原文不加前缀。

每次比较都会重新计算所选片段的向量，数量多时可能较慢；进度会显示在网页上。结果只保存在当前网页会话中，不建立持久化索引，不写入聊天历史，也不会调用 DeepSeek。分数不是概率，排名靠前不保证足以回答问题。资料按字符切分而非模型 token 数切分，极端情况下模型可能截断超长输入。

## 第五步：建立最小本地向量索引

先读取并切分资料，再展开“学习：建立本地向量索引”，选择文件并点击“生成并保存本地索引”。每次构建会在 `vector_index/` 新建独立的 JSON 快照，保存模型名称、向量维度，以及每段资料的文字、来源、位置和向量；不会覆盖已有索引。重新启动后可以从网页选择并查看已保存的索引。修改资料后，需要重新读取、切分并生成新的快照。

这是便于学习的平面向量索引，以 JSON 保存全部记录；它不是 Chroma 或近似最近邻索引，也不会自动加速查找。后续比较仍需读取并逐条计算相似度。`vector_index/` 保存了资料原文，已加入 `.gitignore`。构建索引时不调用 DeepSeek；要在聊天中使用索引，还需要选择知识库问答模式。

## 第五步：使用保存的索引检索

展开“学习：使用本地索引检索片段”，选择已有索引、输入问题并点击“使用索引检索”。程序读取已保存的片段向量，只为问题生成新向量，然后逐条计算余弦相似度并展示排名、原文和来源。这个检索演示不调用 DeepSeek；知识库问答模式则会将检索到的片段提供给 DeepSeek。

每个索引是构建时的资料快照；修改资料后需要重新构建。程序会检查索引的格式版本、模型、预处理方式和向量维度是否与当前模型兼容。当前 JSON 平面索引仍需逐条比较，但避免了每次检索都重新生成资料向量。


## 第六步：基于本地索引进行知识库问答

网页提供“普通对话”和“知识库问答”两种模式。普通对话沿用已有的 DeepSeek 聊天；知识库问答需要先更新知识库，然后选择要使用的 Chroma 集合。没有可用集合时，可在页面上传资料或读取已有资料并更新知识库。

在知识库问答中，每次提交问题后，程序先使用当前问题在所选的已保存索引中检索相似度最高的三个片段；检索过程使用本地向量模型，不会重新计算索引内资料的向量。随后程序将参考片段、本次问题和之前的对话发送给 DeepSeek，请模型根据资料作答并标注引用编号。片段内容因此会离开本机，请确认所选资料适合发送到 DeepSeek。

回答下方可展开查看本次参考片段、来源和相似度。参考片段与回答一起保存到 `Histor/` 中对应的 JSON 文件，因此重新加载历史对话时仍可查看当时的资料。相似度并非概率，模型生成的引用和答案也需要结合原文核对；即使选择了前三个片段，也不能保证资料一定足以回答。

检索使用的是本次输入的问题，不会自动把前文代词改写为完整问题；追问时写明主题通常更容易找到相关片段。索引是构建时的快照，不会随 `资料/` 文件变化自动更新；更改资料后请重新读取、切分、生成索引并在问答中选择新的索引。

## 第七步：上传资料并更新知识库

展开网页顶部的“上传资料并更新知识库”，选择一个或多个 TXT、Markdown、PDF 或 DOCX 文件，再点击“上传并更新知识库”。文件会保存在 `资料/上传/`；重名时自动添加编号，不覆盖已有文件。选择文件本身不会开始保存，必须点击按钮。旧版 Word `.doc` 请先另存为 `.docx`；扫描图片 PDF 需要先做 OCR。

程序随后重新读取 `资料/` 中所有支持的文件并切分，使用本地向量模型为所有片段重新生成向量，然后在本地 Chroma 建立新的集合。更新不是增量计算；资料较多时会耗时、占用磁盘。旧集合不会被覆盖，新集合创建成功后网页自动切换为知识库问答并选择新集合。上传和建索引不调用 DeepSeek，提问时才将检索出的片段及对话发送给 DeepSeek。

上传的文件如果没有可提取的正文，不会生成新索引；文件已保存时网页会显示路径。对于其他未能完整读取的资料（例如 PDF 的扫描页），更新后会逐条显示提示，未提取的内容不在索引中。修复资料后可点击“重新读取资料并更新知识库”，无需重新上传已保存的文件。直接在 `资料/` 中增删或修改文件后，也可以用这个按钮重建快照。上传、索引与历史都保存在本机，`资料/上传/` 已加入 `.gitignore`。

## 观察一次知识库问答过程

此前版本的“学习：观察本次知识库问答过程”展示过本次问题、索引、请求状态以及检索片段和相似度；当前页面已移除这个区域。聊天回答下方仍可查看参考片段。相似度是向量比较的结果，不是答案正确的概率，也不作为片段内容发给模型。

此前的过程区域还展示了准备提供给 DeepSeek 的 messages：系统要求、之前对话的角色与内容，以及包含参考片段和当前问题的用户消息。当前页面不展示完整 messages；这些消息依然会按原有知识库问答逻辑发送。

当前不再记录完整请求的过程快照；助手回答和其参考片段仍按原有方式保存在 `Histor/` 历史文件中。

## 本地 Chroma

`chroma_index.py` 使用持久化 Chroma 数据库 `.local/chroma/`。每次更新创建一个独立 collection：保存资料片段、512 维 BGE 向量、来源、页码及位置；完整写入并核对数量后才在网页中列出。查询时继续由本地模型为问题生成向量，按余弦距离检索，并用 `1 - 距离` 计算网页显示的相似度。Chroma 的近似检索结果可能与旧的 JSON 逐条精确比较略有不同。

`.local/` 已加入 `.gitignore`。原 `vector_index/` 的 JSON 快照仍然保留，但当前网页不会直接读取它们。可用 `migrate_json_indexes.py` 将兼容的旧快照复制到 Chroma 并复用其中的向量；原文件不删除，重复执行会复用已导入的相同快照。仅复制数据库或 JSON 索引不能取代对 `资料/` 和 `Histor/` 的备份。

```bash
/Users/yadingyi/miniconda3/envs/application-llm-universe/bin/python -m pip install -r requirements-chroma.txt
/Users/yadingyi/miniconda3/envs/application-llm-universe/bin/python migrate_json_indexes.py
```
